# Работа с R2O

## Описание изменений для выпуска

При изменении поведения программы, исправлении ошибки или оптимизации добавляй
файл `.changes/<краткое-уникальное-имя>.json` **в тот же коммит, что и код**.
Workflow автоматически собирает эти записи между предыдущим опубликованным
релизом и коммитом сборки. Пользователю не нужно отдельно писать описание выпуска.

```json
{
  "component": "Discovery и подключения",
  "notes": [
    "Исправлено повторное подключение после смены сети: старый маршрут больше не блокирует новую попытку."
  ]
}
```

Пиши законченные предложения на русском языке без маркеров списка и эмодзи.
Объясняй фактическое изменение поведения и условия, при которых оно проявляется.
Для нескольких независимых результатов добавляй несколько пунктов. Сверяй текст
с итоговым diff: существовавшее до правки поведение не должно становиться новой
функцией в описании. Если режим экспериментальный или выключен по умолчанию,
укажи это явно. Не обещай ускорение, экономию памяти или работу у всех провайдеров
без подтверждения. Название нового модуля, переменной или теста само по себе не
является пользовательским описанием.

Используй компонент исходного коммита:

| Scope | component |
| --- | --- |
| discovery | Discovery и подключения |
| catalog | Каталог стратегий |
| telegram, tg | Telegram |
| panel, ui | Веб-панель |
| keenetic | Keenetic |
| openwrt | OpenWrt |
| dns | DNS |
| datapath, engine, nfqueue | Обработка трафика |
| firewall, route | Маршрутизация и firewall |
| installer, install, update | Установка и обновление |
| controller | Контроллер |
| остальные | Другие изменения |

Не добавляй пользовательские нововведения для чистого форматирования, тестов,
документации и обслуживания CI. Не называй изменение поведения `fix(ci)` или
`test(...)`: такие коммиты считаются служебными.

Для новой правки создай новый фрагмент; не переиспользуй запись прошлого выпуска.
Не указывай `commit` для фрагмента, который входит в коммит вместе с кодом.
Необязательное поле `commit` с полным SHA применяется только для восстановления
проверенных заметок к уже существующему коммиту. Оно не переносит старые изменения
в новый выпуск: источник должен входить в диапазон выпуска.

Перед завершением проверь `python3 -B scripts/release_notes.py check` и тесты
генератора: `python3 -B scripts/test-release-notes.py` и
`python3 -B scripts/test-release-changelog.py`. В итоговом ответе описывай изменения
так же конкретно, как в добавленных заметках.
