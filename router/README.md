# Службы роутера

`S99r2o` управляет службами на Keenetic Entware и разделе `/opt` в OpenWrt.
Подписанный выпуск хранит сценарий в `router/`; `S99r2o.shim` в каталоге
инициализации системы передаёт управление сценарию из активного выпуска. При
переключении выпуска обновляется и код служб роутера.

Установите уже распакованный локальный пакет, которому вы доверяете:

```sh
router/install.sh /tmp/r2o-bundle r2o-20261018 mipsel
```

Для OpenWrt MIPS32r2 с musl укажите `mipsel-openwrt-musl` вместо `mipsel`.
Для OpenWrt ARM64 с musl укажите `aarch64-openwrt-musl`. Установщик сохраняет
выбранную архитектуру, а менеджер использует её для последующих проверок и
установки обновлений.

Установщик сохраняет существующий `/opt/r2o/config`. При первой установке
`r2o-manager config-init` берёт файл `config.default` за основу и безопасно
переносит совместимые параметры из `/opt/d2k/config`, если файл донора есть.
Он читает назначения как данные, не запускает их, преобразует путь состояния
в `/opt/r2o` и переводит режим Telegram `relay` на локальный `r2o-telegram`.
Значение донора `FLOWS` переносится в `R2O_FLOW_CAPACITY`; служба передаёт его
обоим datapath-процессам, где общий лимит TCP/UDP составляет 75% округлённого
до степени двойки числа слотов.
Неизвестные настройки и старый сокет управления выводятся в JSON как
неподдерживаемые; исходный файл остаётся нетронутым. Повторный запуск не меняет
существующую конфигурацию. Из проверенных полей `state_dir` и `donor_state_dir`
установщик определяет пути каталогов и при первой установке переносит обученный
каталог в `STATE_DIR/catalog.json`. Все сохранённые планы проходят компилятор
R2O, а их заголовки переводятся в формат `r2o-plan`; при ошибке исходный каталог
остаётся на месте. Для нестандартных путей доступны `R2O_DONOR_CATALOG` и
`R2O_TARGET_CATALOG`. Если безопасно определить целевой `STATE_DIR` нельзя,
перенос каталога пропускается. Если найден `/etc/openwrt_release`,
устанавливается связка загрузки OpenWrt. Команда `install-local` доверяет
локальному пакету и не проверяет подпись выпуска.

Служба запускает отдельные процессы `r2o-datapath` и `r2o-controller` для IPv4
и IPv6 и создаёт соответствующие очереди. После привязки обеих очередей она
устанавливает собственную таблицу nftables или цепочки iptables. Оба контроллера
используют `state/catalog.json`; записи сериализуются файловой блокировкой, а
перед сохранением перечитывается текущий снимок. Установите `IPV6_ENABLED=0`
только на роутере без поддержки IPv6 NFQUEUE. Панель слушает loopback, если
владелец не изменил `PANEL_LISTEN`. `PROBE_MARK` задаёт отдельную метку зондов
контроллера (по умолчанию `0`), а `ONLY_MARK` ограничивает обработку выбранной
политикой маршрутизации Keenetic: `МЕТКА[/МАСКА]` или `none`, если политика не
найдена. Шлюз маршрутизации читает правила и выходные интерфейсы через rtnetlink,
следит за обновлениями и оставляет потоки, ушедшие другим маршрутом, ядру.

Прямая команда менеджера `update-install` только активирует выпуск. Панель
передаёт эту операцию сценарию `S99r2o`: он перезапускает службы обеих версий IP,
проверяет очереди и сигнал панели, а при сбое нового выпуска выполняет откат.

При `TG_ENABLED=1` и `TG_MODE=local` служба запускает `r2o-telegram` из
активного выпуска и ждёт сообщения `listener_ready` на закрытом статистическом
сокете. Затем добавляются перенаправления Telegram для IPv4/IPv6 и портов 443
и 5222. Команды `telegram-enable` и `telegram-disable` атомарно меняют
`TG_ENABLED`, управляют процессом и его правилами сетевого экрана. Панель
показывает состояние `local`, когда слушатель готов, и `connected` только после
подтверждённого ответа Telegram.

Служба раз в день проверяет подпись выпуска между 03:00 и 04:59 по местному
времени роутера. Значение `AUTOUPDATE=1` включает установку проверенного
выпуска, а `AUTOUPDATE=0` оставляет ночную проверку без установки. Переключатель
панели обновляет конфигурацию и состояние обновления. Команда очистки найденных
записей останавливает обработчик пакетов и контроллеры, атомарно очищает каталог
под общей блокировкой поиска, а затем запускает службы снова, если они работали.

Проверка на физическом Keenetic или OpenWrt пока не записана.
