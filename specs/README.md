## Архитектурное направление

Существующий конвейер сохраняется: наблюдение потока → измерение → совместимые
кандидаты → ограниченная проверка → точная привязка и компактное наблюдение результата.
На следующем поиске опыт улучшает очередность, но не заменяет проверку применимости.

Различаются три объекта:

| Объект | Для чего используется | Чего он не разрешает |
| --- | --- | --- |
| Подтверждённая привязка | Повторное применение в уже разрешённой точной области | Расширение endpoint, порта, транспорта, семейства или профиля |
| Агрегат исходов | Выбор порядка совместимых кандидатов в подходящем контексте | Превращение локальной ошибки в отрицательный опыт или ACK в прикладной успех |
| Рецепт | Построение нового кандидата по свежим измерениям | Перенос старых численных offsets и чужого подтверждения |

Уже существующие prepared own-first, domain groups, отрицательная история,
measured classifier и forward/reverse/mixed TCP-order учитываются при проектировании.
Следующий синтез расширяет их ограниченным набором соседних гипотез. Конкретные
формула рейтинга, лимиты статистики и представление рецепта выбираются в plan своего
этапа на основе свежего кода и замеров. Нейросеть, отдельный daemon, глобальный перебор
и полная история соединений для этой задачи не нужны.

## Работа через Spec Kit

Использован официальный [Spec Kit v1.4.5](https://github.com/github/spec-kit/releases/tag/v1.4.5),
Codex integration, Bash scripts, стандартный SDD workflow. Шаблоны и skills сгенерированы
CLI; пользовательские решения находятся в constitution и `specs/`. Дополнительные
extensions/presets не установлены. Лицензия: [MIT](../docs/licenses/spec-kit.txt).

На другом ПК установите ту же версию; повторный `init --force` для этого checkout
не требуется:

```sh
uv tool install specify-cli==1.4.5
export SPECIFY_FEATURE_DIRECTORY="$PWD/specs/001-raw-tcp-default"
specify integration status --json
bash .specify/scripts/bash/check-prerequisites.sh --json --require-spec --require-tasks --include-tasks
```

Команды выше выполняются из корня checkout. В актуальном Spec Kit каталог выбирается
через `SPECIFY_FEATURE_DIRECTORY`; один `SPECIFY_FEATURE` не переопределяет указатель
`.specify/feature.json`. Указатель локальный и не коммитится. Передайте переменную
в окружение Codex или явно укажите каталог в запросе к навыку.

Дальше в чате Codex доступны `$speckit-analyze` и, при отдельном задании реализовать
этап, `$speckit-implement`. Для 002/003 сначала `$speckit-plan`, затем `$speckit-tasks`;
старые требования надо обновить по актуальному `main`.
Проверка prerequisites подтверждает наличие документов, а не правильность runtime.

[AGENTS.md](../AGENTS.md). Доказательства исходного состояния и выбранные решения:
