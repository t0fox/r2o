# Runtime Contract: RAW TCP default-on

Этот контракт задаёт целевое поведение следующего изменения, не описывает уже
выпущенное состояние baseline.

## Настройка

Применяется `R2O_RAW_DISCOVERY` после действующего порядка загрузки конфигурации.
Её итоговое значение одинаково трактуется launcher, controller и datapath.

| Итоговое значение | RAW запрошен | Поведение |
| --- | --- | --- |
| Не задано | Да | Новый default-on |
| Пустая строка | Да | Default-on, как shell-подстановка `:-` |
| `0` | Нет | Сохранить явный opt-out после рестарта/обновления |
| `1` | Да | Явное включение |
| Иное непустое значение | Нет | Ограниченная причина некорректной настройки |

Установщик сохраняет явные значения существующего конфига. Новый шаблон может
документировать default, но не является единственным источником поведения.
Существующий порядок приоритетов config/environment не меняется скрыто;
проверяется конечное значение, полученное каждым процессом.

## Фактическая доступность

При разрешённой настройке сохраняются существующие gates: поддерживаемый control
protocol, применяющий режим и активный Discovery. В существующем status/diagnostics
можно различить «запрошено» и «фактически доступно», а также причину различия.
Поле/код выбирается по текущей схеме, отдельный API или UI-переключатель не нужен.
Некорректное значение не останавливает весь R2O и не создаёт бесконечный поток сообщений.

## Каталог и наблюдения

RAW сохраняет только точную транспортную привязку при текущей корреляции ACK.
Нельзя повышать её до прикладной или переносить на другое семейство/порт/profile.
Свежий поток измеряется заново. Перепись старым controller с потерей `raw_profile`
делает RAW-запись непригодной, а не широкой. Новых UDP bindings не возникает.

Отключение через `0` и restart прекращает RAW trials. Полный откат восстанавливает
согласованный набор бинарников, config и catalog из резервной копии при остановленном
сервисе; шаги проверяются действующим механизмом update-rollback.
