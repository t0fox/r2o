# Приёмка RAW TCP Discovery по умолчанию

## База и анализ

База — `main` `19de516fb0b6c21722f4e1c244925307bf5c8f65`. На ней прошли все
21 задания CI. Проверки разработки выполняются на Linux x86_64, ядро
6.18.57, Rust 1.98.0 и действующий nightly для MIPSEL.

Проверка артефактов Spec Kit покрыла FR-001–FR-008 и SC-001–SC-004 задачами
T001–T014. Критических противоречий с конституцией не выявлено. На свежей
базе появились `Components.raw_trials` и снимок datapath для каждого
семейства. Они подходят для статуса RAW и сохраняют действующий путь
сериализации. Учёт транспорта и итог клиентского обмена проверяются отдельно.

На базе launcher устанавливает `R2O_RAW_DISCOVERY=0` при отсутствующем ключе,
а Rust принимает только `1`. UDP и TCP делят четыре активные записи. Переходы
измерение → повтор → исполнение → связанный полный ACK уже существуют.
Проверка `sh scripts/test-router-raw-default.sh` на базе остановилась на первом
случае `unset`, получив `0` вместо `1`.

## Выполненные проверки на ПК

- `sh scripts/test-router-raw-default.sh` — 10/10, включая конфиг старой версии
  без ключа, явное отключение и пустое значение.
- `cargo test --offline --locked -p r2o-controller --test raw_endpoint_discovery --test catalog`
  — 4/4 и 24/24 соответственно. Проверены в том числе точный полный ACK, неверный
  или просроченный ACK, RST, повторное использование tuple, неполный TLS,
  распознанный UDP, насыщение и отправка с ошибкой.
- Тестовый модуль разбора `Setting` из `raw_flow.rs` — 2/2 через `rustc --test`
  без сторонних зависимостей. Сборку всего тестового crate в offline-режиме
  останавливает отсутствующая dev-зависимость `base16ct 0.2.0`.
- `bash scripts/test-router-openwrt-init.sh` — прошли задержка монтирования
  `/opt`, восстановление запуска, изоляция lock/preload и остановка.
- `sh scripts/test-signed-install-rollback.sh` — прошли инициализация настроек,
  обновление слота и откат с сохранением `R2O_RAW_DISCOVERY=0`, отказ повреждённому
  архиву. Применены свежие host dev-сборки controller, datapath, fetch и ранее
  собранные manager, panel, Telegram. Код этих трёх компонентов в этапе не менялся.
- Для `aarch64-unknown-linux-musl` собраны статические ELF aarch64 controller
  и datapath в профиле dev. Оба завершили `--help` через qemu-aarch64 с кодом 0.
- Для `mipsel-unknown-linux-musl` собраны статические ELF32 little-endian
  MIPS32r2 o32 в профиле dev, с OpenWrt SDK и nightly `2026-10-17`.
  Controller и datapath завершили `--help` через qemu-mipsel с кодом 0.
- Проверены 10 фрагментов release notes. Тесты генератора — 13/13 и 26/26.
- Форматирование Rust, синтаксис изменённых shell-скриптов и `git diff --check` прошли.

Полный `r2o-datapath --lib` на хосте — 466 passed, 23 ignored, 20 failed в
control/NFQUEUE/rtnetlink при запрете сетевых операций в рабочей среде. Результат
живого сетевого сценария проверен в изолированном Linux-госте.

## Живой Linux/NFQUEUE

Неизменённая команда CI `sh scripts/test-raw-discovery-nfq.sh` завершилась с кодом
0 в x86_64 QEMU, Linux 6.18.65, nftables 1.1.5. Использованы отдельные namespaces
клиента, роутера и тестового сервера, host dev-бинарники controller/datapath.

| Семейство | RAW не задан | `0` | `1` | Пустое | Некорректное |
| --- | --- | --- | --- | --- | --- |
| IPv4 | Обмен и повтор после рестарта | Обход выключен | Обмен и повтор | Обмен и повтор | Выключен с `invalid-config` |
| IPv6 | Обмен и повтор после рестарта | Обход выключен | Обмен и повтор | — | — |

Без заданного ключа первый ответ клиента получен за 0,783 с для IPv4 и 0,925 с
для IPv6. После перезапуска обоих процессов — 0,914 с и 1,041 с соответственно,
с `own=true`. В каждом включённом случае тест отдельно сверил байты запроса и
ответа, затем сохранённую привязку endpoint/порта/семейства/профиля и `verified_by=8`.
Во всех выключенных случаях peer отфильтровал исходный запрос, привязки не было.
Эти значения характеризуют локальную топологию QEMU и используются для регрессии.

## Открытая приёмка

T012 остаётся открытой. Нет согласованного физического роутера для двух
сопоставимых 10-минутных сессий. Производственный профиль кросс-сборок, полевые
время подбора, число проб, CPU, RSS и пик памяти не измерены.
