# RuTracker через основной R2O

RuTracker использует обычный DNS клиента и обрабатывается общими Discovery и
datapath. Установка R2O больше не включает отдельный прокси или частный DNS
для этого сайта.

При запуске новой версии и восстановлении незавершённой установки R2O читает
журнал прежнего прокси `state/rt-dns/owned.tsv`. На Keenetic
он удаляет записанные в журнале точные пары `ip host` и
`ip name-server` и сохраняет конфигурацию NDM. На OpenWrt он
удаляет собственные значения `dhcp.*.address` и
`dhcp.*.server` через UCI и перечитывает конфигурацию dnsmasq.
Ранее установленные пакеты и пользовательские настройки DNS сохраняются.

После проверки DNS удаляются принадлежавшие прежнему прокси перенаправления.
Затем завершаются опознанные процессы и удаляются их служебные файлы.
Если очистка останавливается, сообщение `r2o миграция RuTracker`
указывает причину. Журнал остаётся доступен для повторной попытки при следующем
запуске установки или службы. Если в UCI есть несохранённые изменения
владельца, сначала завершите свою операцию в UCI или LuCI.

С клиента в LAN проверяйте обычное разрешение имени, загрузку
`https://rutracker.org/` и ресурсов страницы. Если домен ещё
закеширован со старым DNS-ответом, дождитесь истечения TTL.
