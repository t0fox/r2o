Это оценка **доказанного поведения**, а не доли Rust-кода или готовности релиза. Вес 3 означает критичный сетевой контракт или сохранение состояния, вес 2 — важный жизненный цикл/повтор/управление. Балл начисляется только строке со статусом «доказанно эквивалентно» и только за указанное покрытие. «Частично» и «не проверено» дают 0; наличие реализации само по себе балла не даёт. Каждая строка — отдельный проверяемый контракт, всего 89 баллов.

Статусы: **эквивалентно** — есть C/Rust differential-сценарий, подтверждающий перечисленную ветвь; **частично** — часть ветвей подтверждена, но остаётся значимый пробел/различие; **реализовано** — путь есть, прямое сопоставление с C недостаточно; **не проверено** — нет пригодного прогона для вывода.

## Известные расхождения и тестовые ограничения

**Classifier CLEAR confirmation mismatch исправлен.** D2O выполняет два дополнительных whole-trigger зонда после исходного 3/3 и возвращает FLAKY при молчании или транспортном отказе; Rust раньше сразу объявлял CLEAR. Rust теперь подтверждает базу, учитывает transport errors и прекращает классификацию как CLEAR после отмены. C/Rust differential сравнивает CLEAR/5, silent FLAKY/5, refused FLAKY/5 и cancellation INCONCLUSIVE/3. Полное дерево poison/strategy и control/neutral ACK остаётся частично проверенным.

**Classifier SO_MARK confirmation mismatch исправлен, socket integration ещё не подтверждена.** D2O продолжает зонд после отказа установить mark, но запрещает CLEAR, если хоть один probe был unmarked. Rust теперь читает фактический `SO_MARK` normal TCP socket и передаёт unmarked-состояние классификатору, который возвращает INCONCLUSIVE после 5 успешных ответов. C/Rust differential воспроизводит отказ hook и подтверждает classifier outcome; production `getsockopt` path остаётся непроверенным без Linux build/run.

**Classifier timeout mismatch corrected after tracing the production C path.** D2O `detect/classify.c::once_probe` uses the configured timeout for connect and response; `d2k_classify_run` retries a baseline connect deadline once at twice that timeout. The previous five-second result was mapped from the separate `core/meas.c::d2k_meas_once` API. RED reproduced the R2O mismatch: with a 7-second configured deadline, a loopback TLS ServerHello arriving after 5.5 seconds was rejected. R2O now passes the configured duration through connect, response-read, and control-peer probes. The pinned C/Rust classifier differential accepts that reply on both production paths, and the baseline differential confirms 400→800 ms. The targeted Rust socket test passed on Debian 13 WSL2; no QEMU was needed.

**Firewall nft transaction failure mismatch исправлен.** D2O отдаёт ненулевой результат и удаляет свою прежнюю main table после отказа новой транзакции; при чистом запуске его main и RST tables не появляются из-за атомарности одного `nft -f`. Rust раньше терял ненулевой код из-за следующей успешной очистки temp-файла и мог оставить созданную до основной транзакции новую RST table. Теперь Rust возвращает ошибку, удаляет main table и убирает RST table только если она возникла в этой неудачной попытке. `test-firewall-nft-failure-differential.sh` сравнивает код ошибки и состояние обеих таблиц на чистом и уже настроенном состоянии.

**Legacy iptables cleanup mismatch исправлен.** D2O `fw_iptables_down` очищает старые D2K цепочки и hooks перед nft установкой и при остановке; Rust не трогал xtables при nft backend. Differential воспроизвёл оставшийся `D2K_OUT` hook/chain для IPv4 и IPv6 после успешного R2O `up`. Rust теперь снимает старые D2K правила для обоих backend и свои R2O xtables rules при nft `up`/`down`. `test-firewall-nft-legacy-iptables-differential.sh` сверяет все D2K `fw_family_down` пути (HTTP hooks/chains, marks, MASQUERADE и D2K_OUT/IN hooks/chains) на обоих семействах для `up` и `down`; PPE cleanup отдельно не проверен.

**RST nft table lifetime mismatch исправлен.** C `fw_down` удаляет main table, но сохраняет отдельную `d2k_rst` до остановки контроллеров; только полная остановка службы удаляет её. R2O раньше удалял `r2o_rst` внутри `firewall down`, до остановки controller процесса, что могло сорвать активную raw probe. Теперь adapter `down` оставляет RST table, а S99 удаляет её отдельным `rst-down` после engine, panel и log maintenance stop. `test-firewall-nft-down-rst-lifetime-differential.sh` сравнивает intermediate table state и фактический порядок C/Rust full stop; живой параллельный probe не запускался.

**Classifier baseline transport handling исправлен.** C считает серию с ошибкой на каждом базовом подключении `UNREACHABLE` после ровно трёх зондов и продолжает к разрезу, если ошибка была только в части серии. Rust раньше удваивал базовые повторы при dial timeout и прекращал работу при любой ошибке базы. Differential сравнивает all-errors `UNREACHABLE/3` и partial-base-error → split `FLAKY/6`.

**Classifier unproven/control repeats исправлены.** C сохраняет alert как `unproven`, проверяет весь control batch и при alert в trigger плюс успешном control возвращает `INCONCLUSIVE/9`; частичный control или любая transport error дают `FLAKY/9`. Rust раньше терял unproven при базовой серии и останавливал control после первого успеха.
