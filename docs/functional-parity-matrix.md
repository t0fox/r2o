# Матрица функционального паритета D2O → R2O

Аудит среза `2026-10-30`. Эталон D2O: `t0fox/d2o` `304ba893dd37197128ac8799c0495b035f6a38c0` (`main`). Эталон R2O: `t0fox/r2o` `0bd1e1bee134425643a8a01f57a95afbde2c406a` (`origin/main`); локальная ветка основана на этом upstream-коммите и содержит предыдущие audit-документы/тестовые правки плюс исправление bind панели, описанное ниже.

Это оценка **доказанного поведения**, а не доли Rust-кода или готовности релиза. Вес 3 означает критичный сетевой контракт или сохранение состояния, вес 2 — важный жизненный цикл/повтор/управление. Балл начисляется только строке со статусом «доказанно эквивалентно» и только за указанное покрытие. «Частично» и «не проверено» дают 0; наличие реализации само по себе балла не даёт. Каждая строка — отдельный проверяемый контракт, всего 75 баллов.

Статусы: **эквивалентно** — есть C/Rust differential-сценарий, подтверждающий перечисленную ветвь; **частично** — часть ветвей подтверждена, но остаётся значимый пробел/различие; **реализовано** — путь есть, прямое сопоставление с C недостаточно; **не проверено** — нет пригодного прогона для вывода.

**Evidence-weighted parity: 43 / 75 = 57,33%.** Это доля требований матрицы с прямым подтверждением перечисленных C/Rust ветвей. Это не утверждение, что остальная функциональность отсутствует: частично реализованные или только исходниково сверенные ветви оставлены без баллов, пока нет подходящего дифференциала.

В оценку не включены C relay/enrollment серверы D2O и WARP/VPS/relay сценарии: они вне разрешённой целевой архитектуры R2O. Отдельная C11 реализация Telegram не переносится; сравниваются пользовательские функции, при этом Rust donor z2kOW остаётся целевой реализацией.

## Известные расхождения и тестовые ограничения

1. **Discord endpoint B при измерении endpoint A.** В C `on_suspect` ставит новую цель в pending только когда A в `T_VOICE_TRIAL`/`T_VOICE_WATCH`; общий занятый non-WATCHING слот в `T_VOICE_MEASURE` возвращает без сохранения B. Rust при отсутствии active trial вызывает `queue_after_new_session_with_flow`, и `R2oVoiceLatestQueue::offer` удерживает B за активным поиском A. Это исходниковое различие; differential воспроизведения нет. Изменять семантику без Linux-прогона эталона не следует.
2. **Discord постоянный `SET_ADDR` и поздний отказ.** D2O C fixture воспроизвёл поздний NAK: binding остаётся, а scheduler restart повторно отправляет его. Rust rollback при NAK/timeout исправлен; соответствующий Rust fake-datapath trace добавлен, но не собран/не запущен на доступных Windows/Cygwin targets, поэтому эта ветвь пока не получает балл.
3. **Discord durable restart.** C lifecycle helper проверяет reapply с тем же in-memory catalog, Rust trace проверяет disk save/load. Поэтому voice-specific C/Rust process restart не доказан, несмотря на generic catalog file tests.
4. **Panel bind default теперь совпадает с D2O.** Новый шаблон и fallback используют loopback; первая установка преобразует только штатный loopback в выбранный частный RFC1918 LAN IPv4 по selector-алгоритму D2O, а явный адрес владельца сохраняет. При отсутствии частного адреса установка завершается без bind к публичному интерфейсу. C/Rust selector differential и installer fixture прошли.
5. `scripts/ci-differential-shards.sh` перечисляет 53 upstream entries после добавления panel differential; ранее сообщённые 51 сценарий не повторялись. Check scripts и shared fixture входят в манифест отдельно от differential-сценариев.
6. На Windows: manager/panel GNU-host tests и panel fixtures прошли; `test-package-release.sh` прошёл для пяти OpenWrt ABI packages. Новый D2O C Discord lifecycle fixture собран и исполнен через Cygwin GCC. Rust voice differential не собирается на Cygwin (`quinn-udp`: отсутствуют `mmsghdr`/`recvmmsg`, vendored `rustls`/`ring`: несовместимость `SystemRandom`); GNU-host controller check останавливается раньше на Linux-only `libc::clock_gettime`/`CLOCK_MONOTONIC` в datapath. Полный router install lifecycle остановился на Unix file lock. Текущие Linux C/Rust workspace, NFQUEUE/netns, полная QEMU/ABI runtime matrix и 128-МБ нагрузка не запускались. Исторические результаты в `REA_EVIDENCE.md` не считаются текущим прогоном.
