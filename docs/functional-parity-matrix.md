# Матрица функционального паритета D2O → R2O

Аудит среза `2026-10-30`. Эталон D2O: `t0fox/d2o` `304ba893dd37197128ac8799c0495b035f6a38c0` (`main`). Эталон R2O: `t0fox/r2o` `0bd1e1bee134425643a8a01f57a95afbde2c406a` (`origin/main`). Локальный `E:\r2o` содержит только тестовую правку манифеста поверх этого upstream-коммита: `a45ce6ae3457ca3ff309cf4cd9a7534ae283a420`.

Это оценка **доказанного поведения**, а не доли Rust-кода или готовности релиза. Вес 3 означает критичный сетевой контракт или сохранение состояния, вес 2 — важный жизненный цикл/повтор/управление. Балл начисляется только строке со статусом «доказанно эквивалентно» и только за указанное покрытие. «Частично» и «не проверено» дают 0; наличие реализации само по себе балла не даёт. Каждая строка — отдельный проверяемый контракт, всего 75 баллов.

Статусы: **эквивалентно** — есть C/Rust differential-сценарий, подтверждающий перечисленную ветвь; **частично** — часть ветвей подтверждена, но остаётся значимый пробел/различие; **реализовано** — путь есть, прямое сопоставление с C недостаточно; **не проверено** — нет пригодного прогона для вывода.

## Известные расхождения и тестовые ограничения

1. **Discord endpoint B при измерении endpoint A.** В C `on_suspect` ставит новую цель в pending только когда A в `T_VOICE_TRIAL`/`T_VOICE_WATCH`; общий занятый non-WATCHING слот в `T_VOICE_MEASURE` возвращает без сохранения B. Rust при отсутствии active trial вызывает `queue_after_new_session_with_flow`, и `R2oVoiceLatestQueue::offer` удерживает B за активным поиском A. Это исходниковое различие; differential воспроизведения нет. Изменять семантику без Linux-прогона эталона не следует.
2. **Discord постоянный `SET_ADDR` и поздний отказ.** C `voice_confirm` после успешной записи команды добавляет catalog binding и планирует sync; последующий ACK/NAK не откатывает запись, только увеличивает refusal counters. Rust `confirm_r2o_voice_trial` ждёт ACK и удаляет binding из catalog при NAK/timeout. Различается политика ошибки/состояние; differential воспроизведения нет.
3. **Discord durable restart.** C lifecycle helper проверяет reapply с тем же in-memory catalog, Rust trace проверяет disk save/load. Поэтому voice-specific C/Rust process restart не доказан, несмотря на generic catalog file tests.
4. **Panel bind default — намеренное расхождение продукта.** D2O `files/config` и `panel/main.c` используют `127.0.0.1:8090`; R2O `router/config.default`, `S99r2o` и `Config::default` используют `0.0.0.0:8090`. В R2O это закреплено тестом `router_config_default_exposes_panel_on_router_interfaces`, поэтому значение оставлено: изменение на loopback разорвало бы существующий способ доступа к панели с router-интерфейсов. Это не доказательство эквивалентности; учитывать отдельно при выборе требований безопасности/доступности.
5. `scripts/ci-differential-shards.sh` сейчас перечисляет 52 upstream entries: 49 `*-differential.sh` и 3 `*-check.sh`/shared fixture. Пользователь сообщил о прохождении 51 upstream differential-сценария; этот аудит их не повторял. Разница между числом сценариев и файлов манифеста сама по себе не означает недостающий сценарий.
6. На Windows: `cargo fmt --all -- --check` прошёл; `r2k-core` — 43 теста прошли. `cargo test --workspace --locked` не стартовал из-за отсутствующего MSVC `link.exe`. Попытка Rust GNU host упёрлась в Linux-only API (`clock_gettime`/Unix); manager/panel попытки дали ошибки среды/сетевых тестов и не засчитываются как проход. Текущие Linux C/Rust differential, NFQUEUE/netns, полная QEMU/ABI матрица и 128-МБ нагрузка не запускались. Исторические результаты в `REA_EVIDENCE.md` не считаются повторным текущим прогоном.

## Область следующей проверки

Нужна Linux-среда, доступная только на диске E: временные файлы, target directory и compiler/cache также должны находиться на E. Сначала добавить исполняемые C/Rust differential для двух Discord случаев выше и process restart; воспроизвести C oracle, затем при подтверждённом дефекте менять Rust и запускать точечный тест. Далее закрыть панель API/status/error matrix, service/update fault injection и целевые NFQUEUE/QEMU/resource gates. Пока эти пределы не закрыты, 100% не подтверждены.
