# Поиск по IP для TLS без SNI

## Объём переноса

Источник поведения: D2K `e5ae90a6c371008db4db14051fd283c40071fcc4`,
`core/sched.c` (`recall_noname`, `hello_profile_without_sni`, `fill_hellos`,
`JOB_VERIFY`, `verify_confirm`) и `datapath/plans.c` (временная TCP-проба).
Изменение подготовлено поверх R2O `98f36ad7b28ec5e7fee8e838be7e99d7422ad50b`,
с сохранением поступивших параллельно изменений панели.

Перенесён путь распознанного TLS 1.2/1.3 без SNI для IPv4 и IPv6.
Неизвестный RAW TCP/UDP, ECH без известного имени и ранний YouTube preflight
по ранее наблюдавшимся DNS-адресам — отдельные механизмы D2K; этот перенос
их не реализует. Адресный QUIC в R2O уже имеет собственный путь.

## Поведение

1. Полный ClientHello с действительно отсутствующим расширением SNI
   создаёт адресную цель. Повреждённый, пустой или слишком длинный SNI
   не превращается в отсутствие имени. Неизвестный TCP также не становится TLS.
2. Подозрение того же потока поступает в существующую очередь классификации.
   Внутренний ключ IP не отправляется как SNI. Адресные задачи и снимки
   различают серверные порты.
3. Снятый ClientHello проходит capture, wire, cache и ARM_SHAPE с пустым
   `host`, исходными ALPN и TCP-профилем. Для адресной ARM-задачи выбирается
   самый свежий снимок подходящего endpoint. Если снимка нет, используется
   существующий modern/legacy профиль с удалённым расширением SNI.
4. Прямой CLEAR завершает адресную задачу до props, fallback и установки
   кандидата. HTTP volume для неизвестного TLS-приложения не запускается.
5. Кандидат использует существующий R2OP и `SET_NAME_PROBE`. Его служебный
   ключ — канонический `IP:port`/`[IPv6]:port`; это только идентификатор
   control-протокола. Установка, lookup и удаление используют один ключ.
6. Финальный verifier подключается к тому же endpoint, сохраняет ALPN,
   не отправляет SNI или HTTP и проверяет TLS Finished. Modern предлагает
   TLS 1.3/1.2, legacy — только TLS 1.2, как в выбранном донорском пути.
   Один ServerHello или APPLIED не заменяет завершение рукопожатия.
7. Результат хранится как `kind=addr`, `verified_by=5` (PROBE_HANDSHAKE).
   Он не становится HTTP/application proof и не обучает доменную группу.
   Подтверждение сохраняется и при возврате через own-first/props/known.
8. Каталог устанавливает `SET_ADDR` с измеренным TCP-профилем и выбирает
   подходящую свежую привязку. Перепроверка снимает её через `DEL_ADDR`;
   временный опыт снимается через свой `DEL_NAME_PROBE` и trial ID.

## Границы ключей и доказательства

- Временный TCP-план ограничен IP и портом сервера, клиентским портом,
  семейством и формой TLS. Plan/trial ID проверяются существующим APPLIED
  lifecycle. Адрес клиента и controller mark не входят в ключ NameProbe;
  он не является полной направленной пятёркой.
- Постоянная адресная привязка использует существующую модель
  IP + family + shape/TCP profile, без серверного порта, как обычный
  адресный TLS-путь D2K. Endpoint-scoped постоянные service bindings
  требуют отдельного расширения каталога и wire.
- Ключ снимка канонический и не содержит направления ClientHello.
  ARM проверяет принадлежность точного endpoint потоку, контроллер
  дополнительно сверяет цель через существующий `server_of`. Это не
  добавляет независимого доказательства направления для любых портов.
- Handshake proof не подтверждает доверие сертификату, HTTP, воспроизведение
  YouTube или работу произвольного приложения. Измерительный verifier
  сохраняет существующую политику сертификатов; проверка Finished для
  финального адресного пути включена явно.
- Наличие IP-цели не означает, что любой отказ вызван DPI или что возможен
  обход полного отбрасывания трафика по адресу. Классификатор и проверка
  результата остаются обязательными.

## Локальные проверки

Исходный регрессионный тест полного ClientHello без SNI сначала падал в
`DiscoveryTarget::from_event`, затем прошёл после переноса.

Проверены:

- создание и сохранение адресных целей, несовпадение IP/семейства/порта,
  отсутствие доменного обучения, повторное использование совместимого
  знания и точная перепроверка привязки;
- IPv4/IPv6, полные и сегментированные ClientHello, ALPN, повреждённые
  длины/SNI, wire roundtrip, свежесть снимка и endpoint ARM;
- изоляция временных планов по endpoint и клиентскому порту, trial ID,
  чужой APPLIED, адресный fallback и контекстные TCP-формы;
- реальные TLS-записи через rustls client/server: корректный handshake,
  неверный Finished для TLS 1.2/1.3, незавершённость после ServerHello,
  modern с согласованием TLS 1.2, запрет повышения legacy до TLS 1.3;
- TCP loopback verifier с ALPN `h2`: SNI отсутствует, HTTP и прочие
  прикладные байты не отправляются, результат только handshake-level.

Выполнены следующие проверки; обе проверки компиляции и адресные bin/lib
тесты повторены после совмещения со свежим `main`:

| --- | --- |
| `cargo check --locked -p r2o-controller -p r2o-datapath --all-targets` | Прошла |
| `cargo check --locked --release -p r2o-controller -p r2o-datapath --bins` | Прошла, без тестовой конфигурации |
| `cargo test --locked -p r2o-controller --bin r2o-controller address_` | 13 прошли |
| `cargo test --locked -p r2o-controller --lib address_` | 13 прошли |

| `cargo test -p r2k-core --lib client_shape_no_sni_tests` | 2 прошли |
| Целевые datapath-фильтры `no_sni`, `malformed_or_oversized_sni`, `endpoint_tls_probe`, `tls_address_context_plans` | 7 новых тестов прошли |
| `rustfmt --check` для изменённых Rust-файлов, `git diff --check` | Прошли |

Фильтры частично пересекаются; результаты не суммируются в число уникальных
тестов. Проверка release-конфигурации — `cargo check`, не сборка или замер
размера исполняемого файла для роутера.

Часть полного набора control-server тестов использует UnixListener и
останавливается в этой среде с `Operation not permitted`: 70 тестов
прошли, 16 остановились на создании Unix-сокета. Это не зелёный полный
набор. Целевые тесты нового пакетного пути и TCP loopback выполнены отдельно.

Полевой NFQUEUE, NAT/марки на роутере, OpenWrt/musl cross-build, soak,
CPU/RSS/размер установки и средние времена 60/15 секунд здесь не измерялись.
Для приёмки нужны чистый штатный каталог, реальный клиент и независимые
повторы с учётом неудач. TLS handshake и сохранение IP-привязки не должны
останавливать таймер достижения прикладного результата.
