# R2O Universal Update Engine

База исходников — опубликованный выпуск `r2o-20261122-1125-6b5c711-45017277844-1` и коммит `6b5c711c`. Первый подписанный пакет, собранный с этим обновлятором, становится началом истории формата 2. Для прежних пакетов предусмотрена чистая установка. В этой ветке релиз ещё не опубликован.

## Причины отказов

- Долгая команда установки занимала общий флаг управления панели. Состояние команды жило в памяти процесса, который сам перезапускался при установке.
- Манифест и подпись скачивались через два независимых запроса к изменяемому адресу `latest`. Публикация между запросами могла дать несовпавшую пару. Архив загружался только с GitHub, а обрыв приводил к удалению частичного файла.
- Менеджер копировал архив в рабочий каталог, а после распаковки снова копировал дерево релиза при активации. Расход места зависел от фазы, а точный размер распаковки заранее отсутствовал.
- Переключение слотов и запись результата проверки разделялись. Сбой после переключения мог оставить активный выпуск до проверки служб. Адаптер после первой успешной пробы ждал фиксированные 60 секунд.

## Архитектура

Панель принимает команды того же источника и запускает Rust-процесс `r2o-manager`. Панель читает локальный статус по `GET /api/update` и список проверенных версий по `GET /api/update/catalog`. Проверка обновлений и установка используют отдельный флаг панели. Блокировка менеджера действует между процессами, в том числе после перезапуска панели. До опасной фазы можно запросить отмену.

1. **CHECK.** GitHub Releases определяет опубликованный стабильный тег. Менеджер проверяет Ed25519 каталога, привязку к тегу и возрастающий порядковый номер. Выбранный манифест скачивается по закреплённому тегу и сверяется с каталогом.
2. **DOWNLOAD.** Менеджер резервирует место по подписанным размерам. Rust HTTPS измеряет скорость пробных диапазонов и пробует источники по порядку. Частичный архив хранится под именем подписанного SHA-256. Ответ `206` должен содержать точные значения `Content-Range` и длины. Ответ `200` начинает загрузку файла заново. После возобновления проверяется хеш всего архива.
3. **VERIFY и STAGE.** Менеджер проверяет хеш, правила распаковки, лимиты, архитектуру ELF и ожидаемый загрузчик. Проверенное дерево синхронизируется с диском до остановки служб.
4. **MIGRATE.** Менеджер сверяет контракт форматов и проверяет схему обученного каталога. Выпуски формата пакета 2 разделяют форматы конфигурации и состояния версии 1. Миграция телеметрии обновлятора выполняется атомарной записью. Переход на будущие форматы пользовательских данных потребует реализованной прямой и обратной миграции.
5. **ACTIVATE.** Менеджер синхронизирует журнал на диске, останавливает службы через адаптер, переносит готовое дерево и атомарно записывает слоты. Рабочий предшественник сохраняется. Конфигурация и каталог остаются в общих путях вне слотов.
6. **HEALTH CHECK и COMMIT.** Проверяется активный слот и несколько последовательных проб служб. Адаптер проверяет NFQUEUE для включённых семейств, сокеты и публикацию статуса контроллера, правила firewall, DNS recovery, HTTP API панели и готовность включённого Telegram. После успеха Rust отмечает фиксацию в журнале и обновляет историю. При отказе восстанавливает прежний слот. Временный процесс восстановления остаётся доступным после остановки панели и при аварийном завершении основного процесса. При старте OpenWrt или Keenetic журнал обрабатывается до обычного запуска служб.

## Матрица совместимости

| Установленный выпуск | Целевой выпуск | Поведение |
|---|---|---|
| Установка отсутствует | Первый выпуск формата 2 | Чистая подписанная установка. |
| Пакет прежнего формата | Любой выпуск формата 2 | Менеджер отклоняет сетевое обновление имеющейся установки. |
| Формат пакета 2, конфигурация 1, состояние 1 | Более новый выпуск той же схемы и ABI | Обновление с теми же пользовательскими данными. |
| Формат пакета 2, конфигурация 1, состояние 1 | Более старый опубликованный выпуск той же схемы и ABI | Явный downgrade через каталог. Предыдущий локальный слот доступен без сети. |
| Любой поддерживаемый выпуск | Неизвестная схема или другой ABI | Отказ до остановки служб и переключения слотов. |

## Публикация зеркала

Workflow проверяет подпись и архивы в черновике GitHub Releases. Если настроено R2, он копирует оригинальные файлы и сравнивает скачанные байты. Указатель зеркала меняется после проверки обязательных файлов и публикации тега в GitHub. Для R2 нужны переменные `R2O_R2_PUBLIC_URL`, `R2O_R2_ENDPOINT`, `R2O_R2_BUCKET` и секреты `R2O_R2_ACCESS_KEY_ID`, `R2O_R2_SECRET_ACCESS_KEY` в окружении подписи. Публичные прокси получают только ссылки на публичные активы.

## Проверка

Команды локального прогона

```sh
cargo fmt --all --check
cargo check --locked --workspace --all-targets
cargo test --locked -p r2o-manager -p r2o-panel --all-targets
sh scripts/test-package-release.sh
sh scripts/test-router-install-bootstrap.sh
sh scripts/test-router-update-lifecycle.sh
R2O_PANEL_BIN=target/debug/r2o-panel node crates/r2o-panel/tests/browser.cjs
```

Сценарий аварийного отключения в полном OpenWrt QEMU принимает исходное ядро, сжатый ext4-образ, ARM64-менеджер и каталог логов. Адаптер теста отмечает момент после переключения слотов, QEMU выключается принудительно и загружается снова с тем же диском. Проверяются восстановленный слот, журнал и сохранность файлов пользователя. Сценарий использует управляемый адаптер и не измеряет реальный датапат.

```sh
python3 scripts/test-router-update-powercut-qemu.py KERNEL ROOTFS_GZIP ARM64_MANAGER LOGS
```

Отдельной проверки требуют реальный трафик IPv4/IPv6, состояние NFQUEUE и DNS при перезапуске служб, восстановление Telegram, сбой питания физического накопителя, скорость WAN и доступность зеркал у операторов. Релизный запуск публикации и доступ к рабочему R2 не проводились.

### Выполненные проверки

- До ошибки WSL прошли 36 тестов библиотеки менеджера, 17 CLI-тестов и 32 теста панели. `cargo check --locked --workspace --all-targets` завершился успешно. После этих прогонов были внесены небольшие правки начального статуса, bootstrap и тестового QEMU-скрипта.
- CLI-сценарии проверили отказ неизвестной схемы каталога, этапы активации и повторной установки, возврат рабочего выпуска после ошибки запуска, запрет второй установки, запрет поздней отмены и восстановление после SIGKILL. Прогон 17 CLI-тестов занял около 7,05 с со службами из фикстуры.
- Тест упаковки прошёл для 12 ABI с файловыми фикстурами. Проверка поведения при выключенной панели прошла с извлечённым эталоном D2O и локальной фикстурой служб. Синтаксис JavaScript, двух Python-скриптов и Git diff проверены из Windows.
- Сборка x86_64/musl создала статический бинарник промежуточной ревизии. Повторная сборка финального кандидата для ABI OpenWrt и полный сценарий QEMU остались без результата. Диск WSL на C: перестал монтироваться на запись во время проверок.
- Первый браузерный прогон обнаружил лишний запрос каталога в простое. Второй дошёл до прежней фикстуры тайм-аута. Фикстура обновлена под сохранённый статус менеджера, но итоговый прогон браузера прерван сбоем WSL.

### Замеры доступности

Из Windows для одного запроса `Range: bytes=0-16383` к архиву текущего публичного релиза все четыре пути вернули HTTP 206 и 16 384 байта.

| Источник | Время ответа |
|---|---:|
| GitHub | 1,79 с |
| gh-proxy.com | 2,86 с |
| ghfast.top | 2,90 с |
| ghproxy.net | 11,92 с |

Этот замер фиксирует доступность диапазона с данного хоста. Пиковые RAM и диск новой установки, время полного обновления на роутере и реальное сетевое переключение источника после обрыва ещё требуют измерения.
