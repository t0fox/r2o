# Meta Protection

Карточка Meta Protection находится на экране «Обзор». Настройка хранится в каталоге состояния роутера. При выключении адаптер останавливает планировщик и снимает записи, которыми управляет R2O. Общий Discovery по-прежнему обрабатывает обычный трафик.

## Источники

| Источник | Что используется |
| --- | --- |
| v2fly/domain-list-community | Список Meta и его включения Facebook, Instagram, Messenger, Oculus, Threads и WhatsApp |
| tickcount/iplists | Домены Meta и дополнительный список CIDR |
| itdoginfo/allow-domains | Домены Meta и справочные сети IPv4/IPv6 |
| rezmoss/cloud-provider-ip-addresses | Справочные CIDR Meta из плоского текстового экспорта |
| amartinawi/whatsapp-domains | Имена WhatsApp. Шаблоны отбрасываются |
| Dushnilin/tachyon-lists | Домены Meta и Quest, справочные CIDR |
| ipverse/as-ip-blocks | Объявленные сети AS32934, AS63293 и AS54115 отдельно для IPv4 и IPv6 |

Данные загружаются по HTTPS. Планировщик проверяет TTL источников с интервалом в час. Список, подпадающий под ограничения размера и формата, получает SHA-256 и время синхронизации. При ошибке источника сохраняется последняя рабочая версия. Справочные CIDR из сторонних наборов учитываются в базе, а для проверки принадлежности используются ASN-снимки ipverse и резервный список R2O. Netify публикует справочные карточки приложений, а его машинный набор доменов требует подписки.

Контроллер добавляет в очередь точные имена из видимого TLS SNI и QUIC Initial, а также из обычных DNS-вопросов, уже попавших в датапат. Проверка TLS может добавить точные SAN из доверенного сертификата. Внутреннее имя ECH недоступно пассивному наблюдателю.

## Проверка и восстановление

A и AAAA поступают от нескольких DoH-резолверов с bootstrap IP. При отсутствии подходящего ответа планировщик обращается к DoT и DoQ контроллера. Системный DNS используется для диагностики. Принадлежность адреса префиксу Meta, TCP и проверка доверенной цепочки сертификатов с точным SNI требуются до закрепления адреса. HTTP-статус записывается отдельно, если сервер ответил на HEAD.

Для недавно наблюдавшегося имени сетевой сбой на адресе из защищённого DNS может создать точечную задачу в общем Discovery. Рабочий результат сохраняется штатным каталогом Discovery. Карточка отдельно показывает DNS, TLS, результаты поиска и записи R2O.

OpenWrt публикует IPv4 и IPv6 в одном файле `/tmp/hosts/r2o-meta`. R2O атомарно заменяет файл и отправляет `SIGHUP` запущенным экземплярам dnsmasq, которые читают этот каталог. При использовании procd jail проверяется, что экземпляр монтирует каталог целиком. Если экземпляр использует `ignore_hosts_dir`, закрепление Meta для него пропускается.

Штатное обновление записей обходится без изменения UCI и без перезапуска dnsmasq. После прерывания между заменой файла и сигналом планировщик повторяет отправку `SIGHUP`. После перезагрузки временный файл создаётся заново по результатам проверки адресов.

При переходе со старой версии R2O удаляет из сохранённого `dhcp` только секции, для которых журнал владения и все поля совпадают. Если в UCI есть несохранённые изменения, миграция откладывается. Старые записи из конфигурации запущенного dnsmasq действуют до его следующего штатного перезапуска. В течение этого времени R2O откладывает публикацию новых адресов для тех же имён.

На Keenetic используется адаптер `ndmc ip host` для IPv4. AAAA разрешается, проверяется и отображается и на Keenetic, где поддержка закрепления AAAA зависит от прошивки.
