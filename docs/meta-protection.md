# Meta Protection

Карточка Meta Protection находится на экране «Обзор». Настройка хранится в каталоге состояния роутера. При выключении адаптер останавливает планировщик и снимает записи, которыми управляет R2O. Общий Discovery по-прежнему обрабатывает обычный трафик.

## Источники

| Источник | Что используется |
| --- | --- |
| v2fly/domain-list-community | Список Meta и его включения Facebook, Instagram, Messenger, Oculus, Threads и WhatsApp |
| tickcount/iplists | Домены Meta и дополнительный список CIDR |
| itdoginfo/allow-domains | Домены Meta и справочные сети IPv4/IPv6 |
| rezmoss/cloud-provider-ip-addresses | Справочные CIDR Meta из плоского текстового экспорта |
| amartinawi/whatsapp-domains | Имена WhatsApp. Шаблоны отбрасываются |
| Dushnilin/tachyon-lists | Домены Meta и Quest, справочные CIDR |
| ipverse/as-ip-blocks | Объявленные сети AS32934, AS63293 и AS54115 отдельно для IPv4 и IPv6 |

Данные загружаются по HTTPS. Планировщик проверяет TTL источников с интервалом в час. Список, подпадающий под ограничения размера и формата, получает SHA-256 и время синхронизации. При ошибке источника сохраняется последняя рабочая версия. Справочные CIDR из сторонних наборов учитываются в базе, а для проверки принадлежности используются ASN-снимки ipverse и резервный список R2O. Netify публикует справочные карточки приложений, а его машинный набор доменов требует подписки.

Контроллер добавляет в очередь точные имена из видимого TLS SNI и QUIC Initial, а также из обычных DNS-вопросов, уже попавших в датапат. Проверка TLS может добавить точные SAN из доверенного сертификата. Внутреннее имя ECH недоступно пассивному наблюдателю.

## Проверка и восстановление

После включения выполняется начальная проверка. Следующие штатные проверки запускаются раз в сутки в сохранённый случайный момент окна 01:00–04:59 по местным часам роутера. `R2O_INSTAGRAM_REFRESH_AT=HHMM` задаёт другое время. Повторная команда включения уже работающей защиты сохраняет суточное ограничение. Неудачные попытки повторяются с задержкой от 30 минут до суток; переход через полночь эту задержку не сбрасывает. Потеря временного hosts-файла после перезагрузки разрешает восстановление до ночного окна с соблюдением задержки после ошибок.

Кандидатами A и AAAA служат ранее проверенные адреса из локальной базы, ответы системного DNS, нескольких DoH-резолверов с bootstrap IP и резервного DoT/DoQ контроллера. Доступность конкретного зашифрованного резолвера не требуется. Сохранённые и вновь полученные адреса проходят проверку заново: принадлежность префиксу Meta, TCP и доверенная цепочка сертификатов с точным SNI обязательны до закрепления. HTTP-статус записывается отдельно, если сервер ответил на HEAD.

Сетевые пробы одного прохода ограничены общим бюджетом 180 секунд, из которых получение DNS-кандидатов занимает не более 60 секунд. Параллелизм ограничен двумя именами при получении кандидатов и четырьмя проверками TLS. База содержит не более 640 точных имён. Имена, до которых проход не дошёл, не получают отметку выполненной проверки.

Сетевая ошибка или отрицательный результат проверки не удаляют прежнюю привязку автоматически. Для её замены нужен проверенный адрес того же точного имени и семейства IP. На Keenetic новая запись применяется до удаления прежней; ошибка добавления сохраняет старую привязку. При недоступности DNS остаётся возможность проверить подходящие адреса семейства Meta с точным SNI запрошенного имени.

Для недавно наблюдавшегося имени сетевой сбой на адресе из защищённого DNS может создать точечную задачу в общем Discovery. Рабочий результат сохраняется штатным каталогом Discovery. Карточка отдельно показывает DNS, TLS, результаты поиска и записи R2O.

OpenWrt публикует IPv4 и IPv6 в одном файле `/tmp/hosts/r2o-meta`. R2O атомарно заменяет файл и отправляет `SIGHUP` запущенным экземплярам dnsmasq, которые читают этот каталог. При использовании procd jail проверяется, что экземпляр монтирует каталог целиком. Если экземпляр использует `ignore_hosts_dir`, закрепление Meta для него пропускается.

Штатное обновление записей обходится без изменения UCI и без перезапуска dnsmasq. Результаты прохода публикуются одной заменой файла; если содержимое не изменилось и нет незавершённого применения, сигнал не отправляется. `SIGHUP` перечитывает записи и сбрасывает общий DNS-кэш, поэтому частота обновления ограничена расписанием ([документация dnsmasq](https://thekelleys.org.uk/dnsmasq/docs/dnsmasq-man.html)).

Журнал применения хранит поколение hosts-файла и экземпляры, для которых procd подтвердил отправку сигнала. После частичного отказа повторная попытка обращается только к оставшимся экземплярам. Ошибки отправки используют отдельную задержку от минуты до часа; вызовы ubus ограничены временем и объёмом ответа. Если работающий экземпляр с прежними записями больше нельзя безопасно обновить, снятие записей остаётся незавершённым. Перезапуск службы для обхода ошибки не выполняется. Пока применение ожидает повтора, состояние закреплений сохраняет последнее подтверждённое значение и показывает ожидание; после успешного повтора оно обновляется без следующей сетевой проверки.

После перезагрузки временный файл создаётся заново по результатам проверки адресов, в том числе из сохранённой базы. Отключение защиты снимает только принадлежащие R2O записи; база знаний сохраняется для последующего включения.

При переходе со старой версии R2O удаляет из сохранённого `dhcp` только секции, для которых журнал владения и все поля совпадают. Если в UCI есть несохранённые изменения, миграция откладывается. Старые записи из конфигурации запущенного dnsmasq действуют до его следующего штатного перезапуска. В течение этого времени R2O откладывает публикацию новых адресов для тех же имён. Устаревшие конфигурационные файлы остановленных экземпляров не блокируют обновление.

На Keenetic используется адаптер `ndmc ip host` для IPv4. AAAA разрешается, проверяется и отображается и на Keenetic, где поддержка закрепления AAAA зависит от прошивки.

## Проверки изменений

`scripts/test-router-meta-protection.sh` проверяет переключатели защиты и сохранение суточной отметки. Тесты `meta_dns` и `meta_knowledge` проверяют сохранение прежних привязок, работу без ответов DNS, восстановление из базы, бюджет времени, расписание и повторную отправку сигнала отдельным экземплярам.

`scripts/test-meta-dnsmasq-process.py` собирается и запускается на ПК Linux с Rust из `rust-toolchain.toml` и установленным dnsmasq. Он использует текущий код адаптера, временные конфигурации, loopback и свободные высокие порты. Тест проверяет смену A/AAAA, отсутствие лишнего сигнала при неизменном содержимом, восстановление после ошибок и обычные UDP/TCP DNS-запросы параллельно обновлениям. Системные службы и настройки DNS ПК не меняются. Параметр `--build-only` позволяет перенести собранный тест в изолированную Linux-машину, если среда ПК запрещает необходимые dnsmasq сокеты.

Этот тест проверяет настоящий процесс dnsmasq; транспорт procd и монтирование ujail в нём заменены тестовым адаптером. Для их проверки предназначен отдельный `openwrt_procd_hosts_soak` в одноразовой среде OpenWrt. Проверка процесса Linux не заменяет приёмку на физическом роутере.
