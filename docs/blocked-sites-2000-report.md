# Discord и пул заблокированных сайтов: отчёт

Дата: 2026-11-10 (ночь)
Роутер: OpenWrt 25.12.6, mediatek/filogic, release `ea08729`
Клиент: `192.168.1.216` (Windows, Chromium/Electron)
Роутер: `192.168.1.1`, R2O controller/datapath/telegram/rt-proxy запущены

## 1. Discord desktop

### Симптомы

- Окно «Checking for updates...» / «Discord Updater» не закрывалось.
- После ручного запуска главное окно Discord оставалось скрытым, splash был пустым.
- Gateway WebSocket подключался, получал `HELLO`, отправлял `IDENTIFY`, но не получал `READY` и закрывался с кодом `1006`.

### Что показали реальные логи и трафик

- Updater (`%APPDATA%\discord\logs\Discord_updater_rCURRENT.log`) на первых попытках получал:
  `ConnectionReset (os error 10054)` на
  `https://updates.discord.com/distributions/app/manifests/latest?...`
  после ~19 секунд. Затем повторял запрос; в части запусков третья попытка проходила и писала `Already up to date`.
- CDP-перехват gateway показал последовательность:
  `HELLO` → `IDENTIFY` (с токеном) → закрытие `1006` без `READY`.
- Контрольный gateway-клиент с тем же токеном получил от Discord
  `4004 Authentication failed`. Это доказало, что токен в профиле недействителен,
  а не что R2O не пропускает `READY`.
- Пустое splash-окно было связано с аппаратным ускорением: с `--disable-gpu`
  splash закрывался, главное окно появлялось.

### Исправления

1. Профиль `%APPDATA%\discord` сохранён в
   `%APPDATA%\discord.backup-20261110-002954` и создан заново (сброс недействительного токена).
2. В `%APPDATA%\discord\settings.json` добавлено:
   ```json
   "enableHardwareAcceleration": false
   ```
   Это постоянный фикс зависания splash/главного окна, не требующий флагов ярлыка.
3. Каталог R2O: для `gateway.discord.gg` экспериментально привязан план
   `9f4e96197945de3b0e2a8adb04e8b740` (split/reverse) вместо `dafba69a...`;
   это изменение ещё требует проверки после входа в аккаунт.

### Текущее состояние

- Discord открывает `https://discord.com/login` (HTTP 200, 77 539 байт, 0,38 с).
- `remote-auth-gateway.discord.gg` отвечает 403 (TLS работает), `gateway.discord.gg` — 404 (TLS работает).
- CDP показывает форму входа: email/телефон, пароль, QR-вход.
- **Нужен ручной вход пользователя** (пароль/2FA/QR). Без него нельзя проверить
  `READY`, список гильдий и полноценную работу Discord desktop.

## 2. Пул заблокированных сайтов и прогон 2000

### Источники

- `https://antifilter.download/list/domains.lst` — полный публичный реестр,
  34,6 МБ, 1 792 108 строк; после очистки 1 774 881 уникальный ASCII-домен.
- `https://community.antifilter.download/list/domains.lst` — 485 курируемых доменов.
- Пересечение полного реестра с Tranco top-1M — 11 149 популярных живых
  заблокированных доменов.
- Итоговый список для прогона: приоритетные Discord/Instagram/YouTube/RuTracker
  + community + популярные заблокированные домены.

### Методика

- HTTPS `HEAD /` с клиента `192.168.1.216`, то есть через R2O datapath.
- 30 параллельных запросов, таймаут 8 с, без следования редиректам.
- «Прошёл» = получен любой HTTP-ответ (200/3xx/4xx/5xx), либо ответ с
  сертификатом/заголовками, который браузер обработал бы с предупреждением.
- Body не скачивался; это проверка сетевой доступности, а не рендеринга.

### Результаты

| Набор | Проверено | Прошло | Не прошло |
|---|---:|---:|---:|
| community.antifilter | 485 | 330 (321 HTTP + 9 soft) | 155 |
| Популярные заблокированные (Tranco ∩ antifilter) | 2 743 (прогон остановлен после достижения 2 000) | 2 278 (2 257 HTTP + 21 soft) | 465 |
| Уникальных прошедших всего | — | 2 318 | — |
| Отобрано в итоговый пул | — | **2 000** | — |

- Итоговый файл: `docs/blocked-sites-2000.txt` — 2 000 уникальных доменов,
  Discord-цели идут первыми.
- Основные HTTP-статусы: 200 — 1 086, 301 — 605, 403 — 360, 302 — 134,
  404 — 32; остальные — 3xx/4xx/5xx и soft-ответы.
- Типовые причины отказов: `TIMEOUT` (300), `HARD_TIMEOUT` (111),
  `ECONNRESET` (22), `ENOTFOUND` (15), `EPROTO` (13). Часть из них —
  мёртвые/гео-недоступные домены, часть — реальные блокировки.

### Ограничения

- Проверялся только `HEAD /`, без JS, логина и загрузки контента.
- Сертификатные ошибки (14 altname, 4 expired, 3 chain, 1 header overflow)
  засчитаны как soft-pass; в браузере они дают предупреждение.
- Список содержит публичный реестр блокировок, включая пиратские/взрослые
  категории; запросы были только HEAD, без получения содержимого.

```

```

- RSS: controller 7 764 KiB / 23 потока, datapath 6 220 KiB / 3,
  telegram 7 108 KiB / 3, rt-proxy 4 488 KiB / 4.
- conntrack: 1 457 записей; load average 0,25.
- NFQUEUE IPv4/IPv6 привязаны, firewall установлен.

### Обнаруженная проблема Discovery

- В журнале контроллера 480 сообщений «очередь занята» и 194 сообщения
  «десятиминутный предел»; часть задач не ставилась в классификацию при
  всплеске новых SNI.
- `certr.ru` очень долго занимал задачу («поиск исчерпан; задача отдыхает»),
  после чего очередь освободилась.
- Это не помешало прогону 2000 (популярные домены проходили через готовые
  планы/direct), но остаётся реальным ограничением скорости Discovery.
  Следующий production-фикс должен ограничивать время активной задачи и
  не терять задачи при всплеске, сохраняя донорскую ёмкость 64.

## 4. Следующие шаги

1. Пользователю войти в Discord (пароль/2FA/QR) и проверить `READY`,
   список гильдий и сообщения. После входа сравнить планы gateway `9f4e…`
   и `dafba…`, оставить подтверждённый.
2. Проверить YouTube playback (не только HTTP-статус).
3. Исправить Discovery: активные задачи должны освобождать слот по жёсткому
   deadline, а всплеск новых SNI не должен приводить к «очередь занята».
4. Прогнать 2 000 из `docs/blocked-sites-2000.txt` повторно после входа
   в Discord и убедиться, что нет регрессий.
