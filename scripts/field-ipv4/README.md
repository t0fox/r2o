# Сравнение R2O на физическом LAN

Для контрольного прогона поставьте каждый роутер по очереди между одним проводным клиентом и одним портом вышестоящего шлюза. У шлюза должна сохраняться одна WAN-сессия. Запишите адрес выхода, шлюз, MTU, интерфейсы, версию R2O и SHA-256 исходного каталога перед каждым прогоном. Последовательность OpenWrt → KN‑1910 → OpenWrt позволяет обнаружить изменение доступности сервера во время проверки. Если PPPoE завершает сам исследуемый роутер, отметьте смену сессии и внешнего IP. Отдельной серией можно воспроизвести штатный PPPoE на Viva.

Один раз разрешите имена одним DNS-резолвером и сохраните пары имя/IP для всей серии. Проверьте оба адреса X отдельно. Начинайте сравниваемые прогоны с одинакового снимка каталога. Сверяйте также привязку по имени, семейству, форме ClientHello, TCP-профилю и ID плана. Discovery обновляет каталог во время работы. Смена исходного каталога на действующем роутере требует согласованного окна и сохранённого оригинала.

В прогоне 25 ноября 2026 года использовались следующие пары. Для новой серии сохраните дату разрешения и фактический адрес каждой попытки.

### Заголовки пакетов

На компьютере сборки выполните команды для нужной архитектуры в POSIX shell.

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=mipsle GOMIPS=softfloat go build -trimpath -o watch-viva observe_linux.go
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o watch-cudy observe_linux.go
```

Скопируйте соответствующий файл в закрытый временный каталог роутера. В примере ниже `watch` — этот файл. Фильтр в ядре передаёт ему только IPv4- и TCP-заголовки указанного соединения. Содержимое TLS не записывается. Выберите свободный порт клиента для каждой попытки. Порт 0 в аргументе наблюдателя включает все локальные порты к одному IP и порту сервера, что позволяет увидеть временные сокеты Discovery.

```sh
dst=162.159.140.229
p=51903
./watch capture "$lan" "$dst" "$p" 30 443 > "$p.lan" &
./watch capture "$wan" "$dst" "$p" 30 443 > "$p.wan" &
```

Подставьте действительные имена интерфейсов. Для PPPoE можно одновременно запустить `./watch capture-pppoe "$lower" "$dst" "$p" 30 443`. Нижний интерфейс указан в `/proc/net/pppoe`. Запись на физическом интерфейсе показывает пакеты, видимые ядру. Независимую проверку трафика при аппаратном ускорении даёт зеркальный порт вышестоящего коммутатора.

На Windows-клиенте запускайте запросы в одной версии PowerShell через один проводной адаптер.

```powershell
./request.ps1 -InterfaceAlias Ethernet -ServerName x.com -ServerIp 162.159.140.229 -LocalPort 51903
```

Скрипт привязывает IPv4-сокет к интерфейсу и порту, проверяет сертификат по имени и выполняет GET без переадресации. Он записывает UTC, время TCP и TLS, статус HTTP, число байт вместе с заголовками и получение EOF. Для проверки полноты сообщения HTTP, в том числе chunked, повторите с новым портом и сохраните код выхода curl:

```powershell
curl.exe -4 --noproxy '*' --http1.1 --interface $clientIPv4 --local-port 51913 --resolve x.com:443:162.159.140.229 --connect-timeout 6 --max-time 30 -sS -o NUL -w 'HTTP=%{http_code} body=%{size_download} TCP=%{time_connect} TLS=%{time_appconnect}\n' https://x.com/
$LASTEXITCODE
```

### Маршрут, R2O и подтверждение

Снимите `ip -4 rule show`, `/proc/net/netfilter/nfnetlink_queue`, `/tmp/r2o/datapath-health.4.json` до и после попытки. Во время запроса сохраните строку `/proc/net/nf_conntrack` с исходными dst/sport/dport. Снимите `iptables-save -c -t mangle` на Keenetic или таблицу R2O из `nft list ruleset` на OpenWrt. Для каталога, журнала и health-файлов учитывайте настроенные пути. Включайте запись диагностики по согласованию и возвращайте её исходное состояние.

Для IPv4 ядро возвращает интерфейс в атрибуте 4, шлюз в 5, выбранный локальный адрес в 7 и таблицу в 15. Повторите запросы с наблюдаемым TOS, метками из конфигурации и выбранным локальным адресом. Эти запросы повторяют условия проверки в момент сбора. Счётчики R2O относятся ко всем пакетам семейства.

```sh
./watch route "$client" - - 0 0
./watch route "$dst" "$client" "$lan" 0 0
for mark in 0 45 46 47; do ./watch route "$dst" - - "$mark" 0; done
for mark in 46 47; do ./watch route "$dst" "$wan_ip" - "$mark" 0; done
```

Сохраните события нужных целей из `state/diagnostics/report.json`, `/tmp/r2o/live4.json` и `log/r2o-controller.log` сразу после теста. Журналы ротируются. Для временного кандидата свяжите IP, порт зонда, ID попытки и плана с событием APPLIED, затем с TCP sequence/ACK, ответом TLS и результатом HTTP именно этого сокета. Для клиентской попытки сравните обе стороны NAT по порту и исходному sequence. При трансляции порта используйте обратный кортеж conntrack. Отдельно проверьте запрос, запущенный на самом роутере, с тем же IP и SNI. У каждого из трёх источников — клиента, контроллера и локального curl — свой сокет и результат.

Зафиксируйте первый наблюдаемый разрыв для каждой попытки: SYN без SYN-ACK, данные ClientHello без ACK, применённый план без TLS, ответ HTTP без полного тела или полный ответ. Сохраните также один успешно загружающийся контрольный домен. После прогона удалите временную утилиту и рабочие файлы с устройств.
